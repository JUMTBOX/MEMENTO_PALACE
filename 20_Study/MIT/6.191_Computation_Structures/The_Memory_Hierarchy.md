![image](https://computationstructures.org/lectures/caches/slides/Slide02.png)

지난 강의에서는 축소 명령어 집합 컴퓨터인 Beta의 설계를 마무리했습니다. Beta ISA의 단순한 구조 덕분에 각 명령어를 구현하는 데 필요한 회로에는 많은 공통점이 있었습니다. 최종 설계는 몇 개의 주요 빌딩 블록과, 상황에 맞는 입력값을 선택하는 MUX 제어 로직으로 구성됩니다.

MOSFET의 개수를 세고 전파 지연(propagation delay)을 고려해 보면, 3포트 메인 메모리(그림에서 노란색 두 구성 요소)가 공간 측면에서도, 메모리 접근에 필요한 사이클 시간의 비율 측면에서도 가장 비용이 큰 구성 요소라는 것을 금방 알 수 있습니다. 따라서 여러 면에서 우리는 사실상 “컴퓨팅 머신(computing machine)”이라기보다 “메모리 머신(memory machine)”을 가지고 있다고 볼 수 있습니다.

모든 명령어의 실행은 메인 메모리에서 명령어를 가져오는 것으로 시작합니다. 그리고 CPU가 처리하는 모든 데이터는 결국 메인 메모리에서 로드되거나 메인 메모리에 저장됩니다. 자주 사용되는 소수의 변수 값은 CPU의 레지스터 파일에 보관할 수 있지만, 대부분의 실질적인 프로그램은 CPU 데이터패스 내부에 마련된 저장 공간보다 훨씬 많은 데이터를 다룹니다.

실제로 대부분의 현대 컴퓨터의 성능은 CPU와 메인 메모리를 연결하는 통로의 대역폭(bandwidth), 즉 초당 전송 가능한 바이트 수에 의해 제한됩니다. 이를 흔히 **메모리 병목(memory bottleneck)**이라고 합니다. 이번 강의의 목표는 이 병목의 본질을 이해하고, 이 문제를 최대한 줄이기 위해 어떤 아키텍처적 개선을 적용할 수 있는지 살펴보는 것입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide03.png)

우리는 용량, 지연 시간(latency), 대역폭, 에너지 효율, 비용 측면에서 매우 다양한 특성을 가진 여러 메모리 기술을 사용할 수 있습니다. 당연하게도 각각의 기술은 전체 시스템 아키텍처에서 서로 다른 용도에 적합합니다.

레지스터는 순차 논리(sequential logic)로 구성되며, 최대 수천 비트 정도의 데이터에 대해 약 20ps 수준의 매우 짧은 접근 지연을 제공합니다. 뒤에서 자세히 살펴볼 정적 메모리와 동적 메모리는 더 긴 접근 지연을 감수하는 대신 훨씬 큰 용량을 제공합니다.

정적 랜덤 액세스 메모리(SRAM)는 수천 개 이상의 위치에 대해 최대 수 ns 수준의 짧은 지연을 제공하도록 설계됩니다. 여기서 이미 **저장 위치가 많아질수록 접근 지연이 길어진다**는 사실을 확인할 수 있습니다. 이는 현재 메모리 아키텍처에서 근본적으로 존재하는 **크기와 성능 사이의 트레이드오프**입니다.

비트 수가 증가하면 메모리 회로에 필요한 면적이 늘어나며, 이는 더 긴 신호선을 필요로 합니다. 긴 신호선은 커패시턴스 부하를 증가시키고, 그 결과 회로의 동작 속도가 느려집니다.

동적 랜덤 액세스 메모리(DRAM)는 접근 지연을 희생하는 대신 높은 용량과 저비용에 최적화되어 있습니다. 이번 강의에서 살펴보겠지만, SRAM과 DRAM을 함께 사용하여 **낮은 평균 지연 시간과 높은 용량을 동시에 제공하는 하이브리드 메모리 계층(memory hierarchy)**을 구축할 것입니다. 두 세계의 장점을 모두 얻으려는 것입니다.

여기서 성능 설명에 “평균(average)”이라는 단어가 슬쩍 들어갔다는 점에 주목하십시오. 이는 낮은 지연과 높은 용량이라는 목표를 달성하기 위해 **메모리 접근의 통계적 특성**에 의존한다는 뜻입니다.

최악의 경우에는 여전히 SRAM의 제한된 용량과 DRAM의 긴 지연 시간을 그대로 겪게 됩니다. 하지만 그러한 최악의 상황이 매우 드물게 발생하도록 설계할 것입니다.

플래시 메모리와 하드 디스크 드라이브는 **비휘발성(non-volatile) 저장장치**를 제공합니다. 비휘발성이란 전원이 꺼져도 메모리에 저장된 내용이 유지된다는 의미입니다.

하드 디스크는 메모리 계층의 가장 아래쪽에 위치하며 매우 낮은 비용으로 막대한 장기 저장 공간을 제공합니다.

플래시 메모리는 하드 디스크보다 접근 지연이 약 100배 개선되어 있으며, SRAM과 DRAM을 함께 사용하는 것과 유사한 방식으로 하드 디스크와 함께 사용되기도 합니다. 즉, 높은 용량을 유지하면서 비휘발성 저장장치의 지연을 개선하는 하이브리드 시스템을 구축할 수 있습니다.

이제 이 네 가지 메모리 기술을 조금 더 자세히 살펴본 다음, 다시 메모리 시스템을 구축하는 문제로 돌아가겠습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide04.png)

SRAM은 메모리 위치(memory location)의 배열 형태로 구성됩니다. 한 번의 메모리 접근은 하나의 위치에 있는 모든 비트를 읽거나 쓰는 방식으로 수행됩니다.

여기에는 8개의 위치를 가진 SRAM 배열의 구성 요소 배치가 나타나 있으며, 각 위치에는 6비트의 데이터가 저장됩니다.

개별 비트 셀(bit cell)은 8개의 행과 6개의 열로 구성됩니다.

* 각 행은 하나의 메모리 위치를 나타냅니다.
* 각 열은 각 메모리 워드에서 하나의 비트를 나타냅니다.

배열의 주변부에 있는 회로는 주소를 디코딩하고 읽기 및 쓰기 동작을 지원합니다.

SRAM에 접근하려면 원하는 위치를 유일하게 지정할 수 있을 만큼 충분한 주소 비트가 필요합니다. 이 경우 8개의 메모리 위치 중 하나를 선택하려면 3비트의 주소가 필요합니다.

주소 디코더는 8개의 워드라인(wordline, 배열의 수평선) 중 하나를 HIGH로 만들어 해당 행, 즉 메모리 위치를 활성화합니다. 나머지 워드라인은 LOW로 유지되어 해당 셀들을 비활성화합니다.

활성화된 워드라인은 선택된 행의 SRAM 비트 셀을 각각 비트라인(bitline, 배열의 수직선) 쌍에 연결합니다.

읽기 동작에서는 비트라인이 활성화된 비트 셀의 아날로그 신호를 센스 앰프(sense amplifier)로 전달하고, 센스 앰프는 이를 디지털 데이터로 변환합니다.

쓰기 동작에서는 입력 데이터를 비트라인에 인가하고, 활성화된 비트 셀에 저장합니다.

더 큰 SRAM은 비트라인의 길이, 따라서 커패시턴스를 최소화하기 위해 더 복잡한 구조를 사용합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide05.png)

SRAM의 핵심은 **비트 셀(bit cell)**입니다.

일반적인 SRAM 셀은 두 개의 CMOS 인버터를 양의 피드백 루프(positive feedback loop) 형태로 연결하여 **쌍안정 저장 소자(bistable storage element)**를 만듭니다.

오른쪽 그림은 두 개의 안정 상태를 보여줍니다.

위쪽 구성에서는 셀이 1비트를 저장하고 있으며, 아래쪽 구성에서는 0비트를 저장하고 있습니다.

이 셀은 전원이 공급되는 동안 안정적으로 값을 저장합니다. 인버터의 노이즈 내성 덕분에 입력에 어느 정도의 전기적 잡음이 발생하더라도 논리값이 유지됩니다.

피드백 루프의 양쪽은 액세스 FET(access FET)를 통해 두 개의 수직 비트라인에 연결됩니다.

액세스 FET의 게이트에 연결된 워드라인이 HIGH이면 FET가 켜지고, 셀 내부 회로와 비트라인이 전기적으로 연결됩니다.

워드라인이 LOW이면 액세스 FET가 꺼지며 쌍안정 피드백 루프가 비트라인으로부터 분리됩니다. 그 결과 전원이 공급되는 한 저장된 값은 계속 유지됩니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide06.png)

읽기 동작이 시작되면 드라이버는 먼저 모든 비트라인을 Vdd, 즉 논리값 1로 충전한 다음 연결을 끊습니다. 따라서 비트라인은 1 상태로 플로팅됩니다.

그 다음 주소 디코더가 하나의 워드라인을 HIGH로 설정해 한 행의 비트 셀을 해당 비트라인에 연결합니다.

선택된 행의 각 셀은 두 비트라인 중 하나를 GND로 끌어내립니다. 이 예에서는 오른쪽 비트라인이 LOW로 내려갑니다.

비트라인의 전압 변화는 느립니다. 비트라인 전체의 커패시턴스가 크고, 셀을 가능한 작게 유지하기 위해 두 인버터의 MOSFET이 작게 만들어져 있기 때문입니다.

큰 커패시턴스는 일부는 비트라인 자체의 길이 때문에 발생하고, 일부는 같은 열에 있는 다른 셀의 액세스 FET에서 발생하는 확산 커패시턴스(diffusion capacitance) 때문입니다.

비트라인이 완전히 유효한 논리 레벨에 도달할 때까지 기다리는 대신, **센스 앰프**가 두 비트라인 사이에 발생하는 작은 전압 차이를 빠르게 감지하여 적절한 디지털 출력값을 생성합니다.

작은 전압 변화를 감지하는 것은 전기적 노이즈에 매우 민감하므로 SRAM은 각 비트마다 한 쌍의 비트라인과 차동 센스 앰프(differential sense amplifier)를 사용하여 노이즈 내성을 높입니다.

보시다시피 저지연 SRAM을 설계하려면 MOSFET의 아날로그 동작에 대한 상당한 전문 지식과, 전기적 노이즈가 회로의 올바른 동작을 방해하지 않도록 하는 세심한 설계가 필요합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide07.png)

쓰기 동작은 먼저 비트라인을 원하는 값으로 구동하는 것으로 시작합니다.

이 예에서는 셀에 0비트를 쓰려고 하므로 왼쪽 비트라인을 GND로, 오른쪽 비트라인을 VDD로 설정합니다.

이전과 마찬가지로 주소 디코더가 하나의 워드라인을 HIGH로 만들어 특정 행의 모든 셀을 쓰기 대상으로 선택합니다.

드라이버의 MOSFET은 셀 내부 인버터에 사용된 MOSFET보다 훨씬 큽니다.

따라서 활성화된 셀 내부의 신호는 비트라인의 값에 의해 강제로 변경되고, 쌍안정 회로는 새로운 안정 상태로 “뒤집힙니다(flip)”.

본질적으로 드라이버의 출력과 내부 인버터의 출력을 서로 단락시키는 것과 비슷하기 때문에, 이 역시 아날로그 동작입니다. 순수한 디지털 회로라면 일반적으로 허용하지 않을 동작입니다.

일반적으로 동일한 폭의 p-FET보다 n-FET이 훨씬 큰 소스-드레인 전류를 전달할 수 있고, n-FET 액세스 트랜지스터의 문턱 전압 강하(threshold drop)까지 고려하면 쓰기 동작의 대부분은 0 값을 가진 비트라인에 연결된 큰 n-FET 풀다운 트랜지스터가 수행합니다.

이 트랜지스터는 셀 내부 인버터의 작은 p-FET 풀업을 쉽게 압도합니다.

따라서 SRAM 설계자는 빠르고 신뢰할 수 있는 쓰기 동작을 보장하기 위해 MOSFET 크기의 균형을 정확히 조정해야 합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide08.png)

SRAM을 여러 개의 읽기/쓰기 포트를 지원하도록 확장하는 것은 어렵지 않습니다. 이는 레지스터 파일 회로에서 매우 유용합니다.

이를 위해 추가적인 워드라인, 비트라인, 드라이버, 센스 앰프 세트를 추가합니다.

이렇게 하면 메모리 배열의 여러 행에 존재하는 쌍안정 저장 소자에 독립적으로 접근할 수 있는 여러 경로가 생깁니다.

N포트 SRAM에서는 각 비트에 대해 다음이 필요합니다.

* N개의 워드라인
* 2N개의 비트라인
* 2N개의 액세스 FET

추가된 워드라인은 셀의 실질적인 높이를 증가시키고, 추가된 비트라인은 셀의 실질적인 폭을 증가시킵니다.

따라서 이러한 배선이 차지하는 면적이 SRAM 전체 크기를 빠르게 지배하게 됩니다.

포트를 추가하면 셀의 높이와 폭이 모두 증가하므로 전체 면적은 읽기/쓰기 포트 수의 **제곱에 비례하여 증가**합니다.

따라서 필요 이상으로 포트를 무분별하게 추가하면 SRAM의 비용이 급격하게 증가할 수 있으므로 주의해야 합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide09.png)

정리하면 SRAM 회로는 비트 셀의 배열 형태로 구성됩니다.

* 각 메모리 위치마다 하나의 행이 존재합니다.
* 메모리 위치의 각 비트마다 하나의 열이 존재합니다.
* 각 비트는 두 개의 인버터를 연결해 만든 쌍안정 저장 소자에 저장됩니다.
* 읽기와 쓰기는 비트라인과 액세스 FET를 통해 수행되는 본질적으로 아날로그적인 동작입니다.

SRAM은 비트 하나를 저장하는 데 6개의 MOSFET을 사용합니다.

더 적게 만들 수 있을까요?

비트 하나를 저장하는 데 필요한 최소 MOSFET 수는 몇 개일까요?

![image](https://computationstructures.org/lectures/caches/slides/Slide10.png)

우선 읽기와 쓰기의 대상 비트를 선택하기 위한 액세스 FET가 최소 하나는 필요합니다.

저장 자체에는 간단한 커패시터를 사용할 수 있습니다. 저장된 비트의 값은 커패시터 양단의 전압으로 표현됩니다.

이렇게 구성한 회로를 **동적 랜덤 액세스 메모리(DRAM) 셀**이라고 합니다.

커패시터의 전압이 특정 임계값을 넘으면 1비트를 저장하고 있다고 판단하고, 그렇지 않으면 0비트를 저장한다고 판단합니다.

커패시터에 저장되는 전하량은 저장된 값을 읽어내는 속도와 신뢰성에 영향을 주며, 이는 커패시턴스에 비례합니다.

커패시턴스를 증가시키려면 다음과 같은 방법을 사용할 수 있습니다.

* 두 전극 사이 절연층의 유전율을 높인다.
* 전극의 면적을 증가시킨다.
* 두 전극 사이의 거리를 줄인다.

이 모든 요소는 지속적으로 개선되고 있습니다.

그림에는 현대 DRAM 셀의 단면이 나타나 있습니다.

커패시터는 집적회로 기판(substrate) 내부 깊숙이 파인 큰 트렌치(trench)에 형성됩니다.

트렌치의 깊이를 늘리면 셀의 평면 면적을 증가시키지 않고도 커패시터 전극의 면적을 늘릴 수 있습니다.

워드라인은 N-FET 액세스 트랜지스터의 게이트 역할을 하며, 이 트랜지스터는 커패시터의 외부 전극을 비트라인에 연결합니다.

매우 얇은 절연층이 외부 전극과 내부 전극을 분리하며, 내부 전극은 기준 전압에 연결됩니다. 그림에서는 GND로 표시되어 있습니다.

`trench capacitor`를 검색하면 커패시터 제작에 사용되는 최신 크기와 재료에 대한 정보를 확인할 수 있습니다.

이 회로는 매우 작습니다. 비트당 면적이 SRAM 비트 셀보다 약 **20배 작습니다.**

하지만 몇 가지 문제가 있습니다.

커패시터의 정전하를 계속 유지해 주는 회로가 없으므로 저장된 전하는 커패시터의 외부 전극에서 서서히 누설됩니다. 이 때문에 **동적(dynamic) 메모리**라는 이름이 붙었습니다.

이러한 누설은 주변 기판과의 PN 접합을 통해 흐르는 작은 피코암페어 수준의 전류나, 액세스 FET가 꺼져 있을 때도 발생하는 서브스레시홀드 전도(subthreshold conduction) 때문에 발생합니다.

따라서 커패시터를 그대로 방치해도 저장된 값을 정상적으로 읽을 수 있는 시간에는 한계가 있습니다.

결국 약 10ms마다 각 비트 셀을 한 번 읽고 다시 써야 합니다. 이를 **리프레시(refresh) 사이클**이라고 하며, DRAM 인터페이스 회로의 복잡성을 증가시킵니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide11.png)

DRAM의 쓰기 동작은 단순합니다.

워드라인을 활성화하여 액세스 FET를 켠 다음, 비트라인을 통해 저장 커패시터를 충전하거나 방전하면 됩니다.

읽기는 조금 더 복잡합니다.

먼저 비트라인을 VDD/2 같은 중간 전압으로 미리 충전(precharge)한 다음 프리차지 회로를 분리합니다.

그 다음 워드라인을 활성화하여 선택된 셀의 저장 커패시터를 비트라인과 연결합니다.

그러면 커패시터에 저장된 전하와 비트라인의 커패시턴스에 저장된 전하가 서로 공유됩니다.

셀 커패시터에 저장된 값이 1이라면 비트라인 전압이 아주 조금, 예를 들어 수십 mV 정도 상승합니다.

저장된 값이 0이라면 비트라인 전압이 조금 감소합니다.

센스 앰프는 이러한 작은 전압 변화를 감지하여 디지털 출력값을 생성합니다.

이 과정에서 **읽기 동작은 비트 셀에 저장된 정보를 파괴합니다.**

따라서 읽기가 끝난 후 감지된 값을 셀에 다시 써 주어야 합니다.

DRAM 회로는 일반적으로 행(row)이 매우 넓도록 구성됩니다. 즉, 연속된 여러 메모리 위치를 한 번의 접근에서 함께 읽습니다.

이 위치 블록은 **DRAM 행 주소(row address)**에 의해 선택됩니다.

그 다음 **DRAM 열 주소(column address)**를 사용하여 이 블록 안에서 반환할 특정 위치를 선택합니다.

동일한 행에서 여러 위치를 읽고 싶다면 새로운 열 주소만 보내면 됩니다. 비트 셀 자체에 다시 접근할 필요 없이 DRAM이 해당 위치를 반환합니다.

따라서 한 행에 대한 **첫 번째 접근은 지연 시간이 길지만, 같은 행에 대한 후속 접근은 매우 짧은 지연으로 처리됩니다.**

뒤에서 보겠지만, 우리는 이러한 빠른 열 접근을 유리하게 활용할 수 있습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide12.png)

정리하면 DRAM 비트 셀은 하나의 액세스 FET와 저장 커패시터로 구성되며, 이 커패시터는 가능한 한 적은 면적을 차지하도록 영리하게 설계됩니다.

DRAM에서는 비트 셀을 읽은 후 그 내용을 다시 써 주어야 하며, 누설 전류로 인해 저장된 전하가 손상되기 전에 모든 셀을 주기적으로 읽고 다시 써서 **리프레시**해야 합니다.

DRAM은 비트 셀이 작기 때문에 SRAM보다 훨씬 높은 용량을 제공합니다.

하지만 DRAM 인터페이스 회로가 복잡하기 때문에 한 행에 대한 최초 접근은 SRAM 접근보다 상당히 느립니다.

반면 동일한 행에 대한 이후 접근은 SRAM에 가까운 속도로 이루어집니다.

SRAM과 DRAM 모두 회로에 전원이 공급되는 동안에는 값을 유지합니다.

하지만 전원이 꺼지면 저장된 비트는 사라집니다.

장기 저장을 위해서는 비휘발성 메모리 기술이 필요합니다. 이것이 다음 강의 부분의 주제입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide13.png)

비휘발성 메모리는 시스템의 전원이 꺼져도 시스템 상태를 유지하기 위해 사용됩니다.

플래시 메모리에서는 **플로팅 게이트(floating gate)**라는 잘 절연된 도체에 전하를 저장함으로써 장기간 데이터를 보존합니다. 이 전하는 수년 동안 안정적으로 유지될 수 있습니다.

플로팅 게이트는 일반 MOSFET 내부에서 MOSFET의 게이트와 채널 사이에 배치됩니다.

플로팅 게이트에 전하가 저장되어 있지 않다면 게이트 단자에 전압 `V1`을 인가하여 MOSFET을 켤 수 있습니다. 즉, 소스와 드레인을 연결하는 반전층(inversion layer)을 형성하여 전류가 흐르게 만들 수 있습니다.

플로팅 게이트에 전하가 저장되어 있다면 MOSFET을 켜기 위해 더 높은 전압 `V2`가 필요합니다.

따라서 게이트 단자에 `V1`과 `V2` 사이의 전압을 인가한 뒤 MOSFET이 전도하는지 확인하면 플로팅 게이트에 전하가 저장되어 있는지 판단할 수 있습니다.

실제로 MOSFET을 흐르는 전류의 크기를 측정할 수 있다면 플로팅 게이트에 저장된 전하량까지 구분할 수 있습니다.

이를 이용하면 하나의 플래시 셀의 플로팅 게이트에 서로 다른 양의 전하를 저장하여 **하나의 셀에 여러 비트를 저장**할 수도 있습니다.

플래시 셀은 병렬 또는 직렬로 연결하여 CMOS NOR 또는 NAND 게이트와 유사한 회로를 구성할 수 있으며, 이를 통해 랜덤 접근 또는 순차 접근에 적합한 다양한 접근 구조를 만들 수 있습니다.

플래시 메모리는 매우 높은 집적도를 가지며, 특히 하나의 셀에 여러 비트를 저장할 경우 DRAM에 가까운 면적 밀도를 달성할 수 있습니다.

NOR 플래시 메모리의 읽기 접근 시간은 DRAM과 비슷한 수십 ns 수준입니다.

NAND 플래시의 읽기 시간은 훨씬 길어서 약 10μs 정도입니다.

모든 종류의 플래시 메모리는 쓰기 시간이 상당히 깁니다. 플로팅 게이트를 둘러싸는 절연 장벽을 전자가 통과하도록 만들기 위해 높은 전압을 사용해야 하기 때문입니다.

플래시 메모리는 일정 횟수 이상 쓰기 작업이 반복되면 절연층이 손상되어 플로팅 게이트가 더 이상 안정적으로 전하를 저장하지 못하게 됩니다.

현재 보장되는 쓰기 횟수는 약 100,000회에서 1,000,000회 정도입니다.

이 한계를 해결하기 위해 플래시 칩은 정교한 주소 매핑 알고리즘을 사용합니다.

따라서 동일한 주소에 반복해서 쓰더라도 실제로는 매번 서로 다른 플래시 셀에 매핑될 수 있습니다.

결론적으로 플래시 메모리는 오랫동안 비휘발성 저장장치의 대표 기술이었던 하드 디스크 드라이브를 **더 높은 성능과 더 높은 비용으로 대체하는 기술**이라고 볼 수 있습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide14.png)

하드 디스크 드라이브(HDD)는 자성 물질이 코팅된 하나 이상의 회전 플래터(platter)를 포함합니다.

플래터는 분당 5,400~15,000회(RPM)의 속도로 회전합니다.

플래터 표면 위에 위치한 읽기/쓰기 헤드는 아래쪽 자성 물질의 자화 방향을 감지하거나 변경할 수 있습니다.

읽기/쓰기 헤드는 액추에이터(actuator)에 장착되어 있으며, 액추에이터는 헤드를 서로 다른 원형 트랙 위로 이동시킬 수 있습니다.

특정 데이터 섹터를 읽으려면 헤드를 올바른 트랙의 반경 위치까지 이동시킨 다음, 원하는 섹터가 헤드 아래까지 회전해 올 때까지 기다려야 합니다.

헤드를 올바른 위치로 이동시키는 데 필요한 평균 총 시간은 약 10ms 수준이므로 하드 디스크의 접근 시간은 상당히 깁니다.

하지만 읽기/쓰기 헤드가 올바른 위치에 도달한 뒤에는 초당 약 100MB 정도의 상당히 괜찮은 속도로 데이터를 전송할 수 있습니다.

반대로 매 접근마다 헤드를 다시 이동시켜야 한다면 실질적인 전송 속도는 약 1,000배 감소하며, 성능은 헤드 재배치 시간에 의해 제한됩니다.

하드 디스크 드라이브는 수 TB의 데이터를 경제적으로 비휘발성 형태로 저장할 수 있지만, 그 대가로 접근 시간이 느립니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide15.png)

이것으로 메모리 기술에 대한 빠른 개요를 마쳤습니다.

각 장치 유형을 조금 더 알아보고 싶다면 Wikipedia의 관련 문서도 유용합니다.

SRAM의 크기와 접근 시간은 집적회로의 크기 및 속도 개선과 함께 꾸준히 발전해 왔습니다.

흥미롭게도 DRAM과 HDD는 용량과 전송률은 크게 향상되었지만 **최초 접근 시간(initial access time)**은 그만큼 빠르게 개선되지 않았습니다.

다행히 지난 10여 년간 플래시 메모리가 프로세서 속도와 HDD 사이의 성능 격차를 메우는 데 도움을 주었습니다.

그러나 프로세서 사이클 시간과 DRAM 접근 시간 사이의 격차는 계속 증가하고 있습니다.

따라서 **낮은 지연과 높은 용량을 동시에 가진 메모리 시스템을 설계하는 일은 점점 더 어려워지고 있습니다.**

사용 가능한 메모리 기술의 용량 차이는 약 **10자릿수(order of magnitude)**에 걸쳐 있으며, 접근 지연의 차이는 약 8자릿수에 달합니다.

이는 속도와 크기 사이의 트레이드오프를 어떻게 조절할 것인지에 대해 상당한 설계상의 문제를 만듭니다.

메모리 계층의 각 단계에는 동일한 근본적인 선택이 존재합니다.

* 작고 빠른 메모리
* 크고 느린 메모리

그런데 이 선택은 조금 불편합니다.

**두 가지 장점을 모두 얻을 방법은 없을까요?**

![image](https://computationstructures.org/lectures/caches/slides/Slide16.png)

우리가 원하는 것은 시스템이 마치 **크고, 빠르고, 저렴한 메인 메모리**를 가진 것처럼 동작하는 것입니다.

하지만 하나의 메모리 기술만으로는 이 목표를 달성할 수 없습니다.

그렇다면 이런 아이디어는 어떨까요?

서로 다른 트레이드오프를 가진 메모리를 계층적으로 구성하여 크고 빠르고 저렴한 메모리와 비슷한 결과를 얻을 수 있을까요?

자주 사용하는 메모리 위치는 SRAM에 저장하여 낮은 지연으로 접근하도록 하고, 나머지 데이터는 더 크고 느린 메모리 구성 요소에 저장할 수 있지 않을까요?

필요할 때마다 데이터를 계층 사이에서 이동시키는 것입니다.

이 아이디어를 계속 따라가 보겠습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide17.png)

두 가지 접근 방법을 생각해 볼 수 있습니다.

첫 번째 방법은 **메모리 계층을 프로그래머에게 노출하는 것**입니다.

각 저장장치 종류를 일정량 제공한 뒤, 특정 계산에서 어떤 메모리 자원을 어디에 배치할 것인지 프로그래머가 직접 결정하도록 하는 것입니다.

프로그래머는 필요할 때 데이터를 빠른 저장장치로 이동하고, 낮은 지연이 더 이상 필요하지 않으면 다시 크고 느린 메모리로 옮기는 코드를 직접 작성합니다.

가장 빠른 메모리는 소량만 존재하므로, 계산의 관심 영역이 바뀔 때마다 데이터가 지속적으로 이동하게 됩니다.

이 접근법에는 유명한 지지자들이 있었습니다.

가장 영향력 있는 사람 중 하나는 슈퍼컴퓨터계의 “스티브 잡스”라고 할 수 있는 **Seymour Cray**였습니다.

Cray는 세 개의 서로 다른 시대에 세계에서 가장 빠른 컴퓨터를 설계했으며, 오늘날 고성능 컴퓨팅의 기반을 이루는 여러 기술을 발명했습니다.

그가 메모리 계층을 관리한 방법은 데이터를 **벡터(vector)**로 구성한 뒤 프로그램이 직접 빠른 메모리 안팎으로 벡터를 이동시키는 방식이었습니다.

특정 종류의 과학 계산에서는 벡터가 실제로 좋은 데이터 추상화였고, 그의 벡터 머신은 여러 해 동안 최고의 컴퓨팅 벤치마크 성능을 기록했습니다.

두 번째 방법은 **메모리 계층을 숨기는 것**입니다.

프로그래머에게는 크고 균일한 하나의 주소 공간만 존재한다고 알려주고, 프로그램은 이를 원하는 대로 사용합니다.

메모리 시스템은 뒤에서 관찰된 사용 패턴에 따라 데이터를 메모리 계층 사이에서 자동으로 이동시킵니다.

이를 위해서는 CPU가 발생시키는 각각의 메모리 접근을 검사하여 요청된 위치가 메모리 계층의 어느 곳에 존재하는지 판단하는 회로가 필요합니다.

그리고 특정 주소 영역이 자주 접근되는 경우, 예를 들어 루프의 명령어를 반복적으로 가져오는 경우라면 메모리 시스템이 해당 접근을 가장 빠른 메모리 구성 요소에 매핑하고 루프 명령어를 자동으로 그곳으로 이동시킬 수 있습니다.

이 모든 동작은 프로그래머에게 완전히 투명합니다.

프로그램은 단순히 명령어를 가져오고 데이터를 접근할 뿐이고, 나머지는 메모리 시스템이 처리합니다.

그렇다면 메모리 시스템이 **올바른 데이터를, 올바른 시점에, 올바른 위치에 자동으로 배치할 수 있을까요?**

Cray는 이 방식에 매우 회의적이었습니다.

그는 유명하게도 다음과 같은 취지의 말을 했습니다.

> 가지고 있지 않은 것을 있는 척할 수는 없다.

프로그램이 데이터를 어떻게 사용할 것인지 알고 있는 프로그래머가 직접 메모리 계층을 관리하는 편이 더 잘할 수 있지 않을까요?

하지만 일반 목적 프로그램을 실행하는 경우에는 실제로 **자동 관리되면서도 낮은 지연과 높은 용량을 제공하고, 하나의 크고 균일한 메모리처럼 보이는 계층형 메모리 시스템**을 만들 수 있습니다.

이를 가능하게 만드는 핵심 통찰은 무엇일까요?

그것이 다음 절의 주제입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide18.png)

그렇다면 메모리 시스템은 어떻게 올바른 데이터를 올바른 시점에 올바른 위치에 둘 수 있을까요?

우리의 목표는 자주 사용되는 데이터를 빠른 SRAM에 두는 것입니다.

그러려면 메모리 시스템이 **앞으로 어떤 메모리 위치가 접근될지 예측**할 수 있어야 합니다.

또한 데이터를 SRAM 안팎으로 이동시키는 오버헤드를 감당할 수 있는 수준으로 유지하려면 한 번 데이터를 이동한 비용을 여러 번의 접근에 걸쳐 분산(amortize)해야 합니다.

즉, SRAM으로 이동시킨 데이터 블록이 여러 번 접근되기를 원합니다.

SRAM에 존재하지 않는 데이터는 더 크고 느린 DRAM, 즉 메인 메모리에 저장됩니다.

시스템이 의도대로 동작한다면 DRAM 접근은 드물게 발생해야 합니다.

예를 들어 새로운 데이터 블록을 SRAM으로 가져와야 할 때 정도에만 DRAM에 접근해야 합니다.

프로그램이 메모리를 어떻게 접근하는지 살펴보면, 실제로 **앞으로 어떤 메모리 위치가 접근될지를 꽤 정확하게 예측할 수 있습니다.**

이를 가능하게 하는 핵심 원칙이 바로 **참조 지역성(locality of reference)**입니다.

참조 지역성은 다음과 같이 말할 수 있습니다.

> 시간 `t`에 주소 `X`에 접근했다면, 가까운 미래에 `X`와 가까운 메모리 위치가 다시 접근될 가능성이 높다.

![image](https://computationstructures.org/lectures/caches/slides/Slide19.png)

프로그램에서 참조 지역성이 왜 나타나는지 이해하기 위해 실행 중인 프로그램이 메모리를 어떻게 접근하는지 살펴보겠습니다.

명령어 fetch는 상당히 예측 가능합니다.

대부분의 경우 현재 명령어 다음 위치에 있는 명령어를 가져오므로 실행은 순차적으로 진행됩니다.

루프를 실행하는 코드는 그림 왼쪽의 시간선처럼 동일한 명령어 시퀀스를 반복해서 가져옵니다.

물론 분기나 서브루틴 호출이 발생하면 순차 실행이 잠시 깨질 수 있습니다.

하지만 곧 다시 연속된 위치의 명령어를 가져오는 형태로 돌아갑니다.

객체지향 언어의 메서드 디스패치 같은 일부 프로그래밍 구조는 시간선 오른쪽처럼 아주 짧은 코드 조각에 대해 흩어진 참조를 만들 수 있지만, 곧 다시 순차적인 접근 형태로 돌아옵니다.

이는 프로그램 실행에 대한 우리의 직관과도 일치합니다.

예를 들어 어떤 프로시저의 첫 번째 명령어를 실행했다면, 그 프로시저의 나머지 명령어도 실행할 가능성이 매우 높습니다.

따라서 프로시저의 첫 번째 명령어가 fetch될 때 해당 프로시저의 코드 전체를 SRAM으로 옮긴다면 이후의 많은 명령어 fetch를 SRAM에서 처리할 수 있을 것입니다.

또한 DRAM에서 블록의 첫 번째 워드를 가져오는 데는 비교적 긴 지연이 필요하지만, 이후 DRAM의 빠른 열 접근을 이용하면 연속 주소의 나머지 워드를 빠르게 스트리밍할 수 있습니다.

따라서 최초 접근 비용을 전체 데이터 전송에 걸쳐 분산할 수 있습니다.

프로시저가 현재 스택 프레임의 인수와 지역 변수에 접근하는 경우도 비슷합니다.

프로시저 코드가 실행되는 동안 작은 메모리 영역에 많은 접근이 발생합니다.

LD와 ST 명령어에 의해 발생하는 데이터 접근에서도 지역성이 나타납니다.

프로그램은 객체나 구조체의 여러 필드에 접근하고 있을 수 있고, 배열의 원소를 순차적으로 탐색하고 있을 수도 있습니다.

또는 시간선 오른쪽 그림처럼 한 배열이나 데이터 객체의 정보를 다른 배열이나 데이터 객체로 이동시킬 수도 있습니다.

시뮬레이션을 통해 특정 시간 구간 동안 서로 다른 메모리 위치가 몇 개나 접근되는지 추정할 수 있습니다.

그 결과 **워킹 셋(working set)**이라는 개념을 발견할 수 있습니다.

워킹 셋은 일정 시간 동안 반복적으로 접근되는 메모리 위치들의 집합입니다.

시간 구간의 크기에 따라 워킹 셋의 크기를 그래프로 그리면 어느 시점부터 워킹 셋 크기가 거의 증가하지 않는다는 것을 볼 수 있습니다.

즉, 시간 구간이 일정 크기 이상이 되면 그 구간에서 접근되는 서로 다른 메모리 위치의 개수는 어느 시점의 구간을 선택하더라도 평균적으로 비슷해집니다.

왼쪽 그래프에서 볼 수 있듯이 실제로 접근되는 주소 자체는 계속 변하지만, 일정 시간 구간 동안 접근되는 **서로 다른 주소의 개수**는 평균적으로 거의 일정합니다.

그리고 놀랍게도 그 수는 그리 크지 않습니다.

따라서 SRAM을 프로그램의 워킹 셋 전체를 담을 수 있을 정도로 크게 만들 수 있다면 대부분의 메모리 접근을 SRAM에서 처리할 수 있습니다.

가끔 새로운 데이터를 SRAM으로 가져오고 오래된 데이터를 DRAM으로 다시 보내야 하지만, DRAM 접근은 SRAM 접근보다 훨씬 드물게 일어납니다.

잠시 후 수학적으로도 살펴보겠지만, 참조 지역성 덕분에 **SRAM처럼 빠르면서 DRAM만큼 큰 용량을 가진 것처럼 동작하는 메모리 시스템**을 SRAM과 DRAM의 조합으로 구성할 수 있게 됩니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide20.png)

계층형 메모리 시스템에서 SRAM으로 구성된 부분을 **캐시(cache)**라고 합니다.

캐시는 최근에 접근한 데이터 블록에 대해 낮은 지연의 접근을 제공합니다.

요청한 데이터가 캐시에 존재한다면 **캐시 히트(cache hit)**라고 하며, SRAM에서 바로 데이터를 제공합니다.

반대로 요청한 데이터가 캐시에 존재하지 않는다면 **캐시 미스(cache miss)**라고 합니다.

이 경우 요청한 위치가 포함된 데이터 블록을 DRAM에서 캐시로 이동해야 합니다.

참조 지역성 원리에 따르면 캐시 미스보다 캐시 히트가 훨씬 자주 발생할 것으로 기대할 수 있습니다.

현대 컴퓨터 시스템은 흔히 여러 단계의 SRAM 캐시를 사용합니다.

CPU에 가까운 캐시 계층은 작지만 매우 빠르고, CPU에서 멀어질수록 캐시는 더 크지만 느려집니다.

어떤 캐시 계층에서 미스가 발생하면 다음 캐시 계층에 접근하고, 거기에서도 미스가 발생하면 다시 다음 단계로 내려갑니다.

결국 필요하다면 DRAM까지 접근하여 최초 요청을 처리합니다.

캐싱은 자주 접근되는 데이터에 대한 접근 속도를 높이기 위해 다양한 분야에서 사용됩니다.

예를 들어 브라우저는 자주 접근한 웹 페이지를 캐시에 보관합니다.

캐시된 복사본이 여전히 유효하다고 판단하면 인터넷을 통해 데이터를 다시 전송받지 않고 로컬 복사본을 사용하여 지연 시간을 줄입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide21.png)

그림은 현대 컴퓨터에서 볼 수 있는 메모리 계층의 한 예입니다.

칩 내부에는 세 단계의 SRAM 캐시가 있고, 그 뒤에 DRAM 메인 메모리가 있으며, 하드 디스크 드라이브 앞에는 플래시 메모리 캐시가 존재합니다.

CPU 레지스터에 어떤 데이터 값을 보관할지, 그리고 어떤 값에 LD와 ST를 사용해야 할지는 **컴파일러**가 결정합니다.

3단계 캐시와 DRAM 접근은 **메모리 시스템의 하드웨어 회로**가 관리합니다.

그보다 아래 단계에서는 접근 시간이 너무 길어집니다. 수백 개 이상의 명령어가 실행될 정도의 시간이 필요하기 때문에, 낮은 계층 사이의 데이터 이동 관리는 소프트웨어에 맡깁니다.

이번 강의에서는 칩 내부 캐시가 어떻게 동작하는지 살펴봅니다.

이후 강의에서는 소프트웨어가 메인 메모리와 비휘발성 저장장치를 어떻게 관리하는지 다룰 것입니다.

하드웨어가 관리하든 소프트웨어가 관리하든, 메모리 시스템의 각 계층은 다음의 더 느린 계층에서 **자주 접근되는 위치에 대해 더 낮은 지연으로 접근할 수 있도록 설계**됩니다.

하지만 뒤에서 살펴보겠듯이, 느린 계층으로 갈수록 구현 전략은 상당히 달라집니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide22.png)

지금까지의 계획을 정리해 봅시다.

프로세서는 캐시에 주소를 보내면서 메모리 접근을 시작합니다.

요청한 주소의 데이터가 캐시에 존재하면 데이터가 빠르게 CPU로 반환됩니다.

요청한 데이터가 캐시에 없다면 **캐시 미스**가 발생합니다.

그러면 캐시는 메인 메모리에 요청하여 데이터를 가져온 뒤 프로세서에 반환합니다.

일반적으로 캐시는 새로 가져온 데이터도 저장합니다. 이 과정에서 오래된 캐시 데이터를 교체할 수도 있습니다.

캐시 접근 시간이 4ns이고 메인 메모리 접근 시간이 40ns라고 가정해 봅시다.

캐시 히트가 발생하면 접근 지연은 4ns입니다.

캐시 미스가 발생하면 접근 지연은 총 44ns입니다.

프로세서는 이렇게 가변적인 메모리 접근 시간을 처리해야 합니다.

단순하게는 접근이 끝날 때까지 기다릴 수 있습니다.

또는 현대의 하이퍼스레딩 프로세서라면 그동안 다른 프로그래밍 스레드의 명령어를 한두 개 실행할 수도 있습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide23.png)

**히트율(hit ratio)**과 **미스율(miss ratio)**은 전체 접근 중 각각 캐시 히트와 캐시 미스가 발생하는 비율을 나타냅니다.

두 비율의 합은 당연히 1입니다.

이 지표를 이용하면 **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**을 계산할 수 있습니다.

항상 캐시를 먼저 확인하므로 모든 접근에는 캐시 접근 시간, 즉 **히트 시간(hit time)**이 포함됩니다.

캐시에서 미스가 발생하면 추가적으로 메인 메모리에 접근하는 시간이 필요합니다.

이 추가 시간을 **미스 패널티(miss penalty)**라고 합니다.

하지만 메인 메모리 접근은 모든 요청에서 발생하는 것이 아니라 일부 요청에서만 발생합니다.

얼마나 자주 발생하는지를 나타내는 값이 미스율입니다.

따라서 AMAT는 다음과 같이 계산할 수 있습니다.

`AMAT = Hit Time + Miss Ratio × Miss Penalty`

미스율이 낮을수록, 다시 말해 히트율이 높을수록 평균 접근 시간은 짧아집니다.

캐시 설계의 목표는 **높은 히트율을 달성하는 것**입니다.

여러 단계의 캐시가 존재한다면 같은 공식을 재귀적으로 적용하여 각 메모리 계층의 AMAT를 계산할 수 있습니다.

뒤쪽의 캐시 계층으로 갈수록 더 느려져 히트 시간이 길어지지만, 캐시 용량이 더 크므로 미스율은 낮아집니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide24.png)

실제 숫자를 대입해 봅시다.

캐시가 응답하는 데 프로세서 사이클 4개가 걸리고, 메인 메모리는 100사이클이 걸린다고 가정합니다.

캐시가 없다면 모든 메모리 접근은 100사이클이 걸립니다.

캐시가 있다면 다음과 같습니다.

* 캐시 히트: 4사이클
* 캐시 미스: 104사이클

캐시를 사용한 AMAT가 100사이클, 즉 캐시를 사용하지 않은 경우와 동일해지는 **손익분기점(break-even point)**을 만들려면 어느 정도의 히트율이 필요할까요?

앞에서 본 AMAT 공식을 적용하면 겨우 **4%의 히트율**만 있어도 `Cache + Main Memory` 시스템이 메인 메모리 단독 시스템과 같은 성능을 낼 수 있습니다.

물론 실제 목표는 이것보다 훨씬 높은 히트율입니다.

AMAT를 5사이클로 만들고 싶다고 가정해 봅시다.

당연히 거의 모든 접근이 캐시 히트여야 합니다.

AMAT 공식을 이용해 필요한 히트율을 계산해 보면 **99%의 접근이 캐시 히트**여야 평균 접근 시간을 5사이클로 만들 수 있습니다.

실제 프로그램에서도 이 정도 성능을 기대할 수 있을까요?

다행히도 상당히 근접할 수 있습니다.

SPEC CPU2000 Benchmark를 대상으로 한 시뮬레이션에서는 표준 크기의 L1 캐시가 약 10조 회의 접근에서 **97.5%의 히트율**을 기록했습니다.

[“All benchmarks” arithmetic-mean 표 참고: http://research.cs.wisc.edu/multifacet/misc/spec2000cache-data/]

![image](https://computationstructures.org/lectures/caches/slides/Slide25.png)

이제 캐시를 직접 만들어 보기 시작하겠습니다.

캐시는 여러 개의 데이터 블록을 저장합니다.

우선은 각 블록이 하나의 메모리 위치라고 가정하겠습니다.

각 데이터 블록에는 해당 데이터의 주소가 **태그(tag)**로 붙습니다.

데이터 블록과 그에 연결된 주소 태그의 조합을 **캐시 라인(cache line)**이라고 합니다.

CPU로부터 주소를 받으면 캐시 내부에서 해당 주소와 일치하는 태그를 가진 블록을 검색합니다.

일치하는 주소 태그를 찾으면 캐시 히트입니다.

읽기 접근이라면 일치하는 캐시 라인의 데이터를 반환합니다.

쓰기 접근이라면 캐시 라인에 저장된 데이터를 수정하고, 어느 시점에는 메인 메모리의 해당 위치도 갱신합니다.

일치하는 태그를 찾지 못하면 캐시 미스입니다.

이 경우 요청된 데이터를 저장할 캐시 라인을 하나 선택해야 합니다.

즉, 기존에 캐시에 저장되어 있던 어떤 위치의 데이터는 더 이상 캐시에 존재하지 않게 됩니다.

읽기라면 메인 메모리에서 요청된 데이터를 가져온 뒤 태그와 데이터 필드를 갱신하여 캐시에 추가하고, CPU에도 데이터를 반환합니다.

쓰기라면 선택된 캐시 라인의 태그와 데이터를 갱신하고, 어느 시점에는 해당 메인 메모리 위치도 갱신합니다.

따라서 캐시의 내용은 CPU가 어떤 메모리 요청을 했느냐에 따라 결정됩니다.

CPU가 최근에 사용했던 주소를 다시 요청한다면 이전 접근에서 가져온 데이터가 아직 캐시에 남아 있을 가능성이 높습니다.

워킹 셋이 서서히 변하면 캐시 내용도 필요에 따라 갱신됩니다.

전체 워킹 셋이 캐시에 들어갈 수 있다면 대부분의 요청은 히트가 되고 AMAT는 캐시 접근 시간에 가까워집니다.

여기까지는 좋습니다.

하지만 캐시 내부를 **빠르게 검색하는 방법**을 마련해야 합니다.

즉, 특정 주소 태그가 어떤 캐시 라인에 존재하는지를 빠르게 판단하는 방법이 필요합니다.

이것이 다음 주제입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide26.png)

가장 단순한 캐시 하드웨어는 SRAM에 몇 가지 추가 로직을 붙인 형태입니다.

이 캐시는 CPU 주소 공간의 각각의 메모리 위치가 **정해진 하나의 캐시 라인**에 매핑되도록 설계됩니다.

그래서 이를 **직접 사상 캐시(Direct-Mapped Cache, DM Cache)**라고 부릅니다.

물론 메모리 위치의 수는 캐시 라인의 수보다 훨씬 많습니다.

따라서 여러 주소가 동일한 캐시 라인에 매핑되며, 캐시는 그중 하나의 주소에 해당하는 데이터만 동시에 보관할 수 있습니다.

DM 캐시의 동작은 간단합니다.

들어오는 주소의 일부를 **인덱스(index)**로 사용하여 검색할 캐시 라인 하나를 선택합니다.

그리고 주소의 나머지 부분을 선택된 캐시 라인의 주소 태그와 비교합니다.

태그가 일치하면 캐시 히트이고, 캐시의 데이터를 즉시 사용하여 요청을 처리할 수 있습니다.

이 설계에는 **valid bit**라는 추가 비트도 포함되어 있습니다.

valid bit가 1이라면 태그와 데이터 필드에 유효한 정보가 들어 있다는 뜻입니다.

캐시에 전원이 들어올 때 모든 캐시 라인의 valid bit를 0으로 초기화합니다.

이는 모든 캐시 라인이 비어 있다는 뜻입니다.

데이터가 캐시로 들어오면 해당 캐시 라인의 태그와 데이터 필드를 채운 뒤 valid bit를 1로 설정합니다.

CPU는 특정 캐시 라인의 valid bit를 다시 0으로 만들도록 요청할 수도 있습니다.

이를 **캐시 플러시(flushing the cache)**라고 합니다.

예를 들어 CPU가 디스크 읽기를 시작하면 디스크 하드웨어가 데이터를 메인 메모리의 특정 블록으로 직접 읽어올 수 있습니다.

이 경우 해당 블록에 대해 캐시에 저장되어 있던 값은 오래된 값이 됩니다.

따라서 CPU는 일치하는 캐시 라인을 invalid 상태로 만들어 해당 위치를 캐시에서 제거할 수 있습니다.

8개의 라인을 가지고 각 캐시 라인이 하나의 워드(4바이트)를 저장하는 작은 DM 캐시를 예로 들어 봅시다.

CPU가 바이트 주소 `0xE8` 위치를 요청했다고 가정합니다.

각 캐시 라인에 4바이트가 들어 있기 때문에 주소의 하위 2비트는 캐시된 워드 안에서의 **바이트 오프셋(byte offset)**을 나타냅니다.

여기서는 캐시가 워드 단위 접근만 처리하므로 바이트 오프셋 비트는 사용하지 않습니다.

그 다음 8개의 캐시 라인 중 하나를 선택하려면 3비트가 필요합니다.

이 **캐시 인덱스 비트(cache index bits)**는 주소의 낮은 비트에서 선택합니다.

왜 낮은 비트를 사용할까요?

**지역성 때문입니다.**

지역성 원리에 따르면 CPU는 가까운 주소들을 연속해서 요청할 가능성이 높습니다.

캐시가 좋은 성능을 내기 위해서는 가까운 위치의 데이터가 동시에 캐시에 존재할 수 있어야 합니다.

따라서 가까운 메모리 위치는 서로 다른 캐시 라인에 매핑되어야 합니다.

가까운 주소들은 주로 하위 주소 비트에서 차이가 나므로 이 하위 비트를 캐시 인덱스로 사용합니다.

그러면 가까운 위치들이 서로 다른 캐시 라인에 매핑됩니다.

캐시 라인 인덱스에 의해 선택된 데이터, 태그, valid bit가 SRAM에서 읽힙니다.

검색을 완료하려면 주소의 나머지 부분을 캐시의 태그 필드와 비교합니다.

두 값이 같고 valid bit가 1이라면 캐시 히트입니다.

그 경우 데이터 필드를 사용해 요청을 처리합니다.

그런데 주소가 32비트인데 왜 태그 필드가 32비트가 아닐까요?

32비트를 모두 저장할 수도 있습니다.

하지만 캐시 라인 2에 들어가는 모든 값은 동일한 인덱스 비트 `0b010`을 가지고 있습니다.

따라서 이미 캐시 라인의 위치 자체로 알 수 있는 인덱스 비트를 태그에 다시 저장할 이유가 없습니다.

즉, 입력 주소로부터 만들어 낼 수 있는 비트를 굳이 SRAM에 저장할 필요가 없습니다.

결과적으로 이 예제의 캐시 하드웨어는 다음 정도로 구성됩니다.

* 8개의 위치 × 60비트 SRAM
* 27비트 비교기 하나
* AND 게이트 하나

캐시 접근 시간은 SRAM 접근 시간에 비교기와 AND 게이트의 전파 지연을 더한 정도입니다.

우리가 기대할 수 있는 수준에서 거의 가장 단순하고 빠른 구조입니다.

이 단순함에는 단점도 있습니다.

CPU 요청 하나에 대해 원하는 데이터가 존재하는지 확인하기 위해 **캐시 위치 하나만 검색**합니다.

엄밀히 말하면 검색이라고 부르기도 민망할 정도입니다.

하지만 주소를 캐시 라인에 매핑하는 방식이 이를 보완해 줍니다.

낮은 주소 비트를 캐시 인덱스로 사용했기 때문에 가까운 메모리 위치는 서로 다른 캐시 라인에 매핑됩니다.

예를 들어 CPU가 8개의 명령어로 이루어진 루프를 실행한다면 8개 명령어가 모두 동시에 캐시에 들어갈 수 있습니다.

더 복잡한 검색 메커니즘을 사용해도 이 경우에는 성능이 더 좋아질 수 없습니다.

결론적으로 **이처럼 극단적으로 단순한 검색 구조만으로도 우리가 중요하게 생각하는 접근 패턴에서는 좋은 캐시 히트율을 얻을 수 있습니다.**

![image](https://computationstructures.org/lectures/caches/slides/Slide27.png)

이번에는 64개의 라인을 가진 DM 캐시를 사용하여 몇 가지 예를 더 살펴보겠습니다.

캐시가 주소 `0x400C`에 대한 읽기 요청을 받았다고 가정합니다.

요청이 어떻게 처리되는지 보기 위해 주소를 이진수로 표현한 뒤 offset, index, tag 필드로 나눕니다.

이 주소에서는 다음과 같습니다.

* offset 비트: 0
* 캐시 라인 index: 3
* tag: `0x40`

따라서 캐시 라인 3의 태그 필드를 주소의 태그 필드와 비교합니다.

두 값이 일치하므로 캐시 히트입니다.

따라서 캐시 라인의 데이터 필드에 있는 값을 사용해 요청을 처리할 수 있습니다.

그렇다면 주소 `0x4008`에 접근하면 캐시 히트일까요?

첫 번째 예와 비슷하지만 이번에는 캐시 라인 인덱스가 3이 아니라 2입니다.

캐시 라인 2를 살펴보면 태그 필드 `0x58`이 주소의 태그 `0x40`과 일치하지 않습니다.

따라서 이 접근은 캐시 미스입니다.

캐시 라인 0, 1, 2가 동일한 태그 값을 가지고 있다면 이 캐시 라인들이 저장하고 있는 워드의 실제 주소는 무엇일까요?

주소 매칭 과정을 반대로 수행하면 됩니다.

이 세 캐시 라인과 일치하는 주소는 그림의 이진수 형태가 되어야 합니다.

상위 주소 비트는 캐시 태그에서 가져오고, 하위 주소 비트는 캐시 라인의 인덱스 값에서 가져옵니다.

인덱스 0, 1, 2를 각각 대입하고 이진수를 16진수로 변환하면 다음 주소를 얻습니다.

* `0x5800`
* `0x5804`
* `0x5808`

즉, 캐시된 위치의 전체 주소는 **캐시 라인의 tag 필드 + 해당 캐시 라인의 index**를 결합하여 구성할 수 있습니다.

CPU가 보낸 주소와 올바르게 비교하려면 캐시에 저장된 정보만으로 원래의 전체 주소를 복원할 수 있어야 합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide28.png)

DM 캐시의 설계를 조금 수정하면 지역성을 더 잘 활용하면서 태그와 valid bit가 차지하는 오버헤드도 줄일 수 있습니다.

캐시 데이터 필드의 크기를 1워드에서 2워드, 4워드 등으로 늘릴 수 있습니다.

각 캐시 라인에 들어 있는 데이터 워드의 개수를 **블록 크기(block size)**라고 하며, 항상 2의 거듭제곱입니다.

블록 크기를 크게 만드는 것은 합리적입니다.

가까운 워드가 곧 접근될 가능성이 높다면 캐시 미스가 발생했을 때 한 워드만 가져오는 대신 더 큰 워드 블록을 함께 가져오는 것입니다.

미스 한 번의 비용은 증가하지만, 이후 접근에서 캐시 히트가 발생할 가능성이 높아집니다.

여기 있는 블록 크기 4의 16워드 DM 캐시와 블록 크기 1의 16워드 DM 캐시를 비교해 봅시다.

블록 크기 4인 캐시에서는 데이터 128비트마다 태그와 valid bit가 총 27비트 존재합니다.

따라서 SRAM 비트의 약 **17%**가 실제 데이터가 아닌 오버헤드입니다.

블록 크기 1인 캐시에서는 데이터 32비트마다 태그와 valid bit 27비트가 존재합니다.

따라서 약 **46%**가 오버헤드입니다.

즉, **블록 크기가 커질수록 SRAM을 더 효율적으로 사용할 수 있습니다.**

각 캐시 라인에는 16바이트의 데이터가 들어 있으므로 이제 4개의 offset 비트가 필요합니다.

캐시는 offset의 상위 2비트를 사용하여 캐시 히트 시 4개의 워드 중 CPU에 반환할 워드를 선택합니다.

캐시 라인은 4개이므로 입력 주소에서 캐시 라인 index로 2비트를 사용합니다.

마지막으로 남은 26개의 주소 비트가 tag 필드가 됩니다.

각 캐시 라인에는 valid bit가 하나만 존재한다는 점에 주목하십시오.

따라서 4워드 블록 전체가 캐시에 존재하거나, 블록 전체가 존재하지 않습니다.

일부 워드만 캐시하는 부분 블록(partial block)을 지원하는 것이 복잡성을 감수할 만큼 가치가 있을까요?

아마 그렇지 않을 것입니다.

지역성에 따르면 나머지 워드도 가까운 미래에 사용할 가능성이 높으므로 함께 캐시에 가져오는 것이 히트율을 개선할 가능성이 큽니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide29.png)

블록 크기와 성능 사이에는 어떤 트레이드오프가 있을까요?

블록 크기를 1보다 크게 만드는 것이 좋다고 했습니다.

그렇다면 블록을 계속 크게 만들면 항상 좋은 것일까요?

블록 크기를 증가시킬 때의 비용과 이점을 살펴봅시다.

블록 크기가 커지면 캐시 미스가 발생했을 때 더 많은 워드를 가져와야 하므로 **미스 패널티는 블록 크기에 비례하여 증가**합니다.

다만 DRAM에서 첫 번째 워드를 가져오는 초기 접근 시간이 상당히 길기 때문에, 블록 크기에 따른 추가적인 미스 패널티가 생각만큼 치명적이지는 않습니다.

블록 크기를 1보다 크게 만들면 캐시 미스 시 주변 워드도 함께 캐시에 가져오기 때문에 이후 접근이 캐시 히트가 될 수 있습니다.

따라서 처음에는 블록 크기를 증가시키면 미스율이 감소합니다.

하지만 전체 캐시 용량을 그대로 유지하면서 블록 크기를 증가시키면 **캐시 라인의 개수는 감소**합니다.

캐시 라인 수가 감소하면 캐시에 동시에 저장할 수 있는 서로 다른 주소 블록의 개수도 감소합니다.

앞서 실행 중인 프로그램의 워킹 셋을 살펴보았듯이, 높은 히트율을 달성하려면 여러 개의 독립된 메모리 영역을 동시에 캐시에 보관해야 합니다.

예를 들면 다음과 같습니다.

* 프로그램 코드
* 스택
* 데이터

따라서 워킹 셋에 존재하는 다양한 주소 블록을 보관할 수 있을 만큼 충분한 수의 캐시 블록을 확보해야 합니다.

결론적으로 **미스율을 최소화하는 최적의 블록 크기가 존재하며, 그 이상으로 블록을 키우면 오히려 역효과가 발생합니다.**

두 그래프의 정보를 AMAT 공식과 결합하면 최적의 AMAT를 제공하는 블록 크기를 선택할 수 있습니다.

현대 프로세서에서는 **64바이트(16워드)** 가 흔한 블록 크기입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide30.png)

DM 캐시에는 치명적인 약점이 하나 있습니다.

3개의 명령어로 이루어진 `LOOPA` 코드를 실행한다고 해 봅시다.

명령어는 워드 주소 1024에서 시작하고, 데이터는 워드 주소 37에서 시작합니다.

프로그램은 명령어와 데이터에 번갈아 접근합니다. 예를 들어 LD 명령어를 수행하는 루프라고 생각하면 됩니다.

블록 크기 1인 1024라인 DM 캐시를 사용한다고 가정합니다.

6개의 위치가 모두 캐시에 한 번씩 로드된 이후에는 각 위치가 서로 다른 캐시 라인에 매핑되므로 정상 상태의 히트율은 **100%**가 됩니다.

이제 동일한 프로그램을 실행하되 데이터 위치만 워드 주소 2048부터 시작하도록 옮겨 봅시다.

이번에는 명령어와 데이터가 동일한 캐시 라인을 놓고 경쟁합니다.

예를 들어 첫 번째 명령어 주소 1024와 첫 번째 데이터 주소 2048은 모두 캐시 라인 0에 매핑됩니다.

따라서 두 값 중 하나만 동시에 캐시에 존재할 수 있습니다.

첫 번째 명령어 fetch가 캐시 라인 0에 주소 1024의 내용을 채웁니다.

그런데 곧이어 첫 번째 데이터 접근에서 캐시 미스가 발생하고, 캐시 라인 0은 주소 2048의 데이터로 다시 채워집니다.

이 데이터 주소는 명령어 주소와 **충돌(conflict)**한다고 합니다.

다음 루프 반복에서 첫 번째 명령어는 더 이상 캐시에 존재하지 않으므로 또 캐시 미스가 발생합니다.

이처럼 주소 충돌 때문에 발생하는 미스를 **충돌 미스(conflict miss)**라고 합니다.

결국 정상 상태에서 캐시는 CPU가 다음에 요청할 워드를 절대로 가지고 있지 않게 됩니다.

상당히 안 좋은 상황입니다.

우리는 단순하고 평평하며 균일한 주소 공간이라는 추상화를 제공하는 메모리 시스템을 만들고 싶었습니다.

그런데 이 예에서는 단지 몇 개의 주소만 바꿨을 뿐인데 캐시 히트율이 **100%에서 0%로 떨어집니다.**

프로그래머 입장에서는 프로그램의 실행 속도가 갑자기 10배 느려지는 현상을 분명하게 느끼게 됩니다.

DM 캐시의 단순성은 마음에 들지만, 충돌 미스로 발생하는 성능 문제를 피하기 위해서는 아키텍처를 변경해야 합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide31.png)

**완전 연관 캐시(Fully-Associative Cache, FA Cache)**는 모든 캐시 라인마다 태그 비교기를 하나씩 가지고 있습니다.

따라서 FA 캐시에서는 **모든 캐시 라인의 태그 필드가 입력 주소의 태그 필드와 동시에 비교**됩니다.

모든 캐시 라인을 검색하기 때문에 특정 메모리 위치는 어떤 캐시 라인에도 저장될 수 있습니다.

그 결과 주소 충돌로 인한 conflict miss 문제가 사라집니다.

그림의 캐시는 주소와 관계없이 서로 다른 4개의 4워드 블록을 저장할 수 있습니다.

앞선 예에서는 루프 명령어 3워드와 데이터 3워드를 동시에 보관할 수 있는 캐시가 필요했습니다.

이 FA 캐시는 두 개의 캐시 라인만 사용하여 두 블록을 저장할 수 있으므로 명령어와 데이터의 주소와 관계없이 100% 히트율을 달성할 수 있습니다.

FA 캐시는 매우 유연하고 대부분의 애플리케이션에서 높은 히트율을 제공합니다.

하지만 단점은 **비용**입니다.

모든 캐시 라인을 병렬로 검색하려면 캐시 라인마다 태그 비교기가 필요합니다.

캐시 라인 수가 많아지면 필요한 회로량이 크게 증가합니다.

저장과 비교 기능을 결합한 **Content-Addressable Memory(CAM)** 같은 회로를 사용하더라도 FA 캐시 전체 비용을 크게 줄이지는 못합니다.

DM 캐시는 캐시 라인 하나만 검색합니다.

FA 캐시는 모든 캐시 라인을 검색합니다.

그렇다면 둘의 중간 정도, 즉 소수의 캐시 라인만 병렬로 검색하는 방법은 없을까요?

있습니다.

여기 있는 FA 캐시의 그림을 자세히 보면 1라인 DM 캐시 네 개가 병렬로 동작하는 것처럼 보입니다.

그렇다면 여러 개의 라인을 가진 DM 캐시 네 개를 병렬로 동작시키면 어떻게 될까요?

![image](https://computationstructures.org/lectures/caches/slides/Slide32.png)

그 결과가 바로 **4-way 집합 연관 캐시(Set-Associative Cache, SA Cache)**입니다.

N-way SA 캐시는 본질적으로 **N개의 DM 캐시를 병렬로 동작시키는 구조**입니다.

각 DM 캐시를 하나의 **서브 캐시(sub-cache)**라고 부르겠습니다.

N개의 서브 캐시는 각각 입력 주소의 index 비트로 선택된 캐시 라인의 tag를 입력 주소의 tag와 비교합니다.

특정 요청에서 검색되는 N개의 캐시 라인을 하나의 **세트(set)**라고 하며, 원하는 데이터는 이 세트에 속한 어느 캐시 라인에든 존재할 수 있습니다.

그림의 4-way SA 캐시는 각 서브 캐시에 8개의 캐시 라인을 가지고 있습니다.

따라서 다음과 같이 구성됩니다.

* 각 set: 4개의 캐시 라인
* 전체 set 개수: 8개

N-way SA 캐시는 동일한 캐시 index에 매핑되는 최대 N개의 블록을 동시에 수용할 수 있습니다.

즉, 최대 N개의 충돌 주소가 존재하더라도 캐시 미스 없이 보관할 수 있습니다.

하나의 주소 충돌만으로 현재 캐시 라인의 데이터를 쫓아내야 했던 DM 캐시보다 크게 개선된 구조입니다.

또한 N-way SA 캐시는 매우 많은 캐시 라인을 가지고 있더라도 **태그 비교기는 N개만 필요**합니다.

캐시 라인 수만큼 비교기가 필요했던 FA 캐시보다 훨씬 저렴합니다.

따라서 N-way SA 캐시는

* 충돌에 취약하지만 저렴한 DM 캐시
* 유연하지만 매우 비싼 FA 캐시

사이의 좋은 절충안입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide33.png)

이번에는 조금 더 자세한 그림으로 3-way, 8-set 캐시를 살펴봅니다.

**way의 개수는 반드시 2의 거듭제곱일 필요가 없습니다.**

주소 비트를 사용해서 특정 way를 선택하지 않기 때문입니다.

따라서 캐시 설계자는 사용 가능한 칩 면적에 맞추어 캐시 용량을 좀 더 세밀하게 조정할 수 있습니다.

용어를 다시 정리해 봅시다.

특정 캐시 index에서 검색되는 N개의 캐시 라인을 **set**이라고 합니다.

그리고 N개의 서브 캐시 각각을 **way**라고 합니다.

각 way의 hit 판단 로직은 다른 way의 로직과 병렬로 동작합니다.

그렇다면 하나의 주소가 둘 이상의 way에서 동시에 일치할 수도 있을까요?

하드웨어 자체가 이를 불가능하게 만드는 것은 아닙니다.

하지만 SA 캐시는 그런 상황이 발생하지 않도록 관리됩니다.

캐시 미스가 발생했을 때 DRAM에서 가져온 데이터를 하나의 서브 캐시에만 저장한다고 가정하면 동일한 주소가 두 개 이상의 서브 캐시에 동시에 존재할 수 없습니다.

어떤 way를 선택할지는 잠시 후에 살펴보겠습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide34.png)

그렇다면 몇 개의 way가 필요할까요?

DM 캐시에서 경험했던 캐시 라인 충돌을 피할 만큼 충분한 way를 원합니다.

앞서 살펴본 시간에 따른 메모리 접근 그래프를 보면 특정 시간 구간 내에서 고려해야 할 잠재적인 주소 충돌의 수가 제한되어 있다는 것을 알 수 있습니다.

주소를 캐시 라인에 매핑하는 방식은 가까운 위치끼리는 충돌하지 않도록 설계되어 있습니다.

따라서 걱정해야 하는 것은 서로 다른 메모리 영역 간의 충돌입니다.

예를 들면 다음과 같습니다.

* 코드
* 스택
* 데이터

그림의 예에서는 이런 영역이 세 개 있습니다.

한 데이터 영역의 내용을 다른 데이터 영역으로 복사하는 경우라면 데이터 영역이 두 개 필요하므로 네 영역 정도가 될 수 있습니다.

시간 구간을 매우 크게 잡으면 시간 구간의 초반 접근과 후반 접근 사이의 충돌까지 고려해야 하므로 그 두 배 정도가 필요할 수도 있습니다.

핵심은 **소수의 way만으로도 대부분의 캐시 라인 충돌을 피할 수 있다는 것**입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide35.png)

블록 크기와 마찬가지로 좋은 것도 지나치면 문제가 됩니다.

AMAT를 최소화하는 **최적의 way 수**가 존재합니다.

그 이상으로 way 수를 늘리면 많은 way의 hit 신호를 결합하기 위한 추가 회로 자체의 전파 지연이 무시할 수 없을 정도로 커집니다.

이 지연은 캐시 hit time에 직접 추가되며 결국 AMAT도 증가시킵니다.

더 중요한 것은 왼쪽 그래프에서 볼 수 있듯이 **4~8 way 이후에는 way 수를 증가시켜도 miss ratio가 거의 개선되지 않는다**는 점입니다.

대부분의 프로그램에서 많은 set을 가진 **8-way set-associative cache**는 같은 용량의 훨씬 비싼 FA 캐시와 거의 비슷한 성능을 냅니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide36.png)

SA 캐시와 FA 캐시에는 마지막으로 해결해야 할 문제가 하나 있습니다.

캐시 미스가 발생했을 때 메인 메모리에서 가져올 데이터를 **어느 캐시 라인에 저장할 것인가?**

DM 캐시에서는 이 문제가 없습니다.

각 데이터 블록은 주소에 의해 결정된 특정 캐시 라인에만 들어갈 수 있기 때문입니다.

하지만 N-way SA 캐시에서는 각 way에 하나씩, 총 N개의 후보 캐시 라인이 존재합니다.

FA 캐시에서는 모든 캐시 라인이 후보가 될 수 있습니다.

그렇다면 어떤 캐시 라인을 선택해야 할까요?

우리의 목표는 앞으로의 **캐시 히트율에 미치는 영향을 최소화하도록 교체할 캐시 라인을 선택하는 것**입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide37.png)

이론적으로 최적의 선택은 **미래에 가장 늦게 다시 접근될 블록**, 혹은 다시는 접근되지 않을 블록을 교체하는 것입니다.

하지만 그러려면 미래를 알아야 합니다.

다른 방법을 생각해 봅시다.

최근의 접근 기록과 지역성 원리를 사용하여 미래의 접근을 예측할 수 있습니다.

오랫동안 접근되지 않은 블록이라면 가까운 미래에도 접근될 가능성이 상대적으로 낮다고 볼 수 있습니다.

이 생각에서 나온 것이 **Least Recently Used(LRU)** 교체 정책입니다.

LRU는 **가장 오래전에 사용된 블록을 교체**합니다.

LRU는 실제로 잘 동작하지만 각 set의 캐시 라인을 마지막 사용 시점에 따라 정렬한 목록을 유지해야 합니다.

그리고 이 목록은 캐시 접근이 발생할 때마다 갱신해야 합니다.

캐시 라인을 교체해야 할 때는 목록의 마지막에 위치한 캐시 라인을 선택합니다.

8-way SA 캐시에는 가능한 순서가 `8!`개 있습니다.

따라서 현재 순서를 인코딩하려면 다음 정도의 상태 비트가 필요합니다.

`log2(8!) = 16 bits`

문제는 캐시 접근마다 이 상태 비트를 갱신하는 로직의 비용이 만만치 않다는 것입니다.

사실상 현재 16비트 상태를 다음 16비트 상태로 변환하는 룩업 테이블이 필요합니다.

따라서 대부분의 캐시는 **LRU를 정확히 구현하지 않고, 갱신 로직이 더 단순한 근사 LRU 정책**을 사용합니다.

다른 교체 정책도 존재합니다.

**FIFO(First-In, First-Out)**에서는 마지막 접근 시점과 관계없이 가장 오래 캐시에 들어 있었던 라인을 교체합니다.

**Random** 정책에서는 일종의 의사 난수 생성기를 사용해 교체할 라인을 선택합니다.

Random을 제외한 모든 교체 정책은 의도적으로 최악의 성능을 만들 수 있습니다.

캐시의 교체 정책을 알고 있다면 캐시가 방금 교체한 주소를 계속 접근하도록 프로그램을 작성하여 극도로 낮은 히트율을 만들 수 있습니다.

물론 일부러 성능이 나쁘도록 작성된 프로그램이 얼마나 잘 동작하느냐를 신경 쓸 필요가 있느냐는 별개의 문제입니다.

중요한 점은 대부분의 교체 정책에서 특정 프로그램이 예상보다 훨씬 느리게 실행되는 상황이 간혹 발생할 수 있다는 것입니다.

결국 **LRU 또는 LRU에 가까운 근사 정책은 합리적인 선택**입니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide38.png)

이제 캐시 설계에서 결정할 문제가 하나만 남았습니다.

메모리 쓰기를 캐시에서 어떻게 처리해야 할까요?

결국 새로운 데이터를 메인 메모리에 반영해야 합니다.

문제는 **언제 반영할 것인가**입니다.

가장 단순한 선택은 즉시 쓰는 것입니다.

즉, CPU가 캐시에 write 요청을 보내면 캐시는 동일한 쓰기를 즉시 메인 메모리에도 수행합니다.

이를 **write-through**라고 합니다.

이렇게 하면 메인 메모리는 항상 모든 메모리 위치의 최신 값을 가지고 있습니다.

하지만 CPU가 DRAM 쓰기가 끝날 때까지 기다려야 한다면 상당히 느려질 수 있습니다.

쓰기가 심각한 병목이 될 수 있습니다.

또한 프로그램이 특정 메모리 위치를 계속 갱신한다고 해봅시다.

예를 들어 현재 스택 프레임의 지역 변수를 반복해서 갱신하는 경우입니다.

결국 메인 메모리에 필요한 것은 **마지막 값 하나뿐**입니다.

그 이전의 모든 값을 메인 메모리에 계속 쓰는 것은 메모리 대역폭의 낭비입니다.

그렇다면 캐시가 메인 메모리에 쓰기를 완료할 때까지 기다리는 동안 CPU는 계속 실행하도록 할 수도 있습니다.

이를 **write-behind**라고 합니다.

이 방식은 느린 메인 메모리 쓰기와 프로그램 실행을 겹쳐서 처리합니다.

하지만 write가 아직 끝나지 않은 상태에서 또 다른 캐시 미스가 발생한다면 문제가 됩니다.

캐시 미스가 해결되어야 CPU가 진행할 수 있기 때문에 기존 write와 새로운 refill read가 모두 끝날 때까지 결국 기다려야 합니다.

더 나은 전략이 **write-back**입니다.

write-back에서는 캐시의 내용만 갱신한 뒤 CPU가 즉시 실행을 계속합니다.

변경된 캐시 값은 해당 캐시 라인이 캐시 미스 처리 과정에서 **교체 대상으로 선택될 때만** 메인 메모리에 기록됩니다.

이 방식은 메인 메모리 접근 횟수를 최소화하고 다른 작업에서 사용할 수 있도록 메모리 대역폭을 보존합니다.

대부분의 현대 프로세서는 이 전략을 사용합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide39.png)

write-back은 구현하기 어렵지 않습니다.

처음 캐시 동작을 설명했던 구조로 돌아가서, CPU가 캐시에 write 요청을 보냈을 때 메인 메모리 쓰기를 시작하는 부분만 제거하면 됩니다.

캐시의 내용만 수정하고 그대로 둡니다.

하지만 캐시 라인을 교체하는 동작은 더 복잡해집니다.

기존 캐시 라인이 이전 write 접근으로 수정된 적이 있다면 해당 캐시 라인을 재사용하기 전에 먼저 그 내용을 메인 메모리에 다시 써야 하기 때문입니다.

그런데 이렇게 구현하면 캐시 라인이 실제로 수정되었는지 여부와 관계없이 **교체되는 모든 캐시 라인을 메인 메모리에 write-back**하게 됩니다.

불필요한 쓰기가 발생합니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide40.png)

불필요한 write-back을 피하기 위해 캐시 라인마다 새로운 상태 비트를 하나 추가할 수 있습니다.

바로 **dirty bit**입니다.

캐시 미스가 발생하여 새로운 데이터로 캐시 라인을 채울 때 dirty bit를 0으로 설정합니다.

이후 write 동작에 의해 해당 캐시 라인의 데이터가 변경되면 dirty bit를 1로 설정합니다.

이는 **캐시에 있는 값과 메인 메모리에 있는 값이 서로 다르다**는 것을 의미합니다.

캐시 라인이 교체 대상으로 선택되었을 때 dirty bit가 1인 경우에만 데이터를 메인 메모리에 다시 쓰면 됩니다.

따라서 dirty bit를 사용하는 write-back 전략은 메인 메모리에 대한 쓰기 횟수를 최소화하는 깔끔한 해결책입니다.

CPU가 지연되는 경우도 캐시 미스가 발생하면서 dirty 캐시 라인을 메인 메모리에 다시 써야 하는 상황으로 제한할 수 있습니다.

![image](https://computationstructures.org/lectures/caches/slides/Slide41.png)

이것으로 캐시에 대한 논의를 마칩니다.

캐시를 도입한 근본적인 목적은 **낮은 지연과 높은 용량을 동시에 가지는 계층형 메모리 시스템을 구축하여 평균 메모리 접근 시간(AMAT)을 최소화하는 것**이었습니다.

이를 위해 여러 가지 전략을 사용했습니다.

**캐시 라인의 수를 증가시키면 미스율이 감소하고, 그 결과 AMAT가 감소합니다.**

**캐시의 블록 크기를 증가시키면 DRAM의 빠른 열 접근을 활용하여 캐시 미스 시 전체 데이터 블록을 효율적으로 가져올 수 있습니다.**

가까운 메모리 위치가 이후 접근될 가능성이 높기 때문에 향후 캐시 히트 수가 증가하여 AMAT를 개선할 것으로 기대할 수 있습니다.

**캐시의 way 수를 증가시키면 캐시 라인 충돌 가능성이 줄어들어 미스율이 감소합니다.**

**교체할 캐시 라인으로 least-recently-used 라인을 선택하면 교체가 히트율에 미치는 영향을 최소화할 수 있습니다.**

마지막으로 쓰기는 **dirty bit를 이용한 write-back 전략**으로 처리하기로 했습니다.

그렇다면 이러한 다양한 아키텍처 선택 사이의 트레이드오프는 어떻게 결정할까요?

늘 그렇듯이 여러 가지 캐시 구성을 시뮬레이션하고, 벤치마크 프로그램에서 가장 높은 성능을 제공하는 아키텍처 조합을 선택하면 됩니다.
