**OS 계정과 권한 - Linux 기준**
- root 계정은 OS를 설치하면 기본 생성되는 계정으로 모든 권한을 가진 관리자 계정
- 파일이나 디렉토리에 대한 권한은 `ls`명령어로 확인 가능 
- `ls -l` 명령어를 사용하면 파일 권한을 포함한 여러 정보 열람 확인 가능
>  파일 권한 | 소유자 | 소유그룹 | 파일크기 | 마지막 수정 시간 | 파일명 <br/>  
> -rw-r--r--. 1 vagrant vagrant  7 11월 10 08:24 README.md <br/>
> -rwxr--r--. 1 vagrant vagrant 28 11월 10 08:26 run.sh 
- `r`: 읽기(Read) 권한 / `4`
- `w`: 쓰기(Write) 권한 / `2`
- `x`: 실행(eXecute) 권한 / `1`
> 소유자  | 그룹 | 다른 계정 <br/>
> -rwx   |  r-- | r--
- `chmod`: 권한 변경
- `$ chmod 754 run.sh` : run.sh 에 (7 / 소유자: 읽기,쓰기,실행), (5 / 그룹: 읽기,실행), (4 / 다른 계정: 읽기) 권한 부여

```shell
# example
$ chmod u+x run.sh  # run.sh파일에 대해 소유자에게 실행 권한 추가
$ chmod g-w run.sh  # run.sh파일에 대해 그룹의 쓰기 권한 제거
$ chmod o=rx run.sh # run.sh파일에 대해 다른 사용자에게 읽기, 실행 권한 지정
```
**sudo로 권한 주기**
- `sudo` 명령어를 사용하면 다른 사용자의 권한으로 프로그램을 실행할 수 있다. <br/>
  (ex. 일반 사용자가 `sudo` 명령어를 통해 root 계정으로 `systemctl` 명령어 사용) 
- `sudo` 명령어로 실행할 수 있는 명령어는 별도 설정 파일로 관리 <br/>
  `/etc/sudoers`파일 혹은 `/etc/sudoers.d`디렉토리에 위치한 파일로 관리

```text
root   ALL=(ALL) ALL
```
- root  -> root 계정은
- ALL   -> 모든 호스트에 대해(실질적으로는 로그인한 서버)
- (ALL) -> 모든 사용자로 실행할 수 있다
- ALL   -> 모든 명령어를 실행할 수 있다

```text
sudoers 파일을 수정할 때는 visudo 명령어를 사용한다.
sudoers 파일은 읽기 전용 파일이기 때문에 vi 명령어로 수정하려면 파일 권한을 수정 전/후에 변경해야 하는데 
visudo 명령어를 사용하면 간편하게 sudoers 파일을 수정할 수 있다
```
- `sudo` 명령어를 실행할 때 권한이 부여된 계정의 비밀번호를 입력해야한다
- 비밀번호 입력 없이 실행할 수 있길 원한다면 `NOPASSWD:` 설정을 추가한다
```text
user1   ALL=(ALL) NOPASSWD: ALL

user1   ALL=(ALL) NOPASSWD: /usr/bin/systemctl start docker
user1   ALL=(ALL) NOPASSWD: /usr/bin/systemctl stop docker
```
**프로세스 확인하기**
- 프로세스 정보 확인: `ps aux`, `ps -eaf`
- CPU나 메모리 사용량 실시간 확인: `htop 프로그램`, `ps aux --sort -rss | head -n 6`(프로세스 메모리 사용량 상위 5개 확인)
- 프로세스 종료: `kill 옵션 PID`
  - -15 또는 -s SIGTERM 또는 -TERM
  - -9 또는 -s SIGKILL 또는 -KILL

```text
-15는 기본값으로, 프로세스에 TERM 신호를 보낸다. TERM 신호를 받은 프로세스는 종료에 필요한 작업을 수행한다.
예를 들어 임시로 생성한 파일을 삭제하거나, 스프링 빈의 제거 처리를 하는 작업을 수행한다.

-9 옵션을 이용하면 프로세스를 강제로 종료한다. 이 옵션은 프로그램이 종료할 때 수행하는 정리 작업을 할 수 없기 때문에 주의해야 한다.
처음부터 -9 옵션으로 프로세스를 죽이기보다는 -15 옵션으로 여러 차례 종료 시도를 했음에도 종료가 되지 않을 때 사용하는 것이 좋다.
```
**백그라운드 프로세스**
- 포그라운드 프로세스(foreground process): 터미널에 연결된 프로세스로, 키보드나 스크린을 통해 사용자와 상호작용함<br/> 
  터미널과 연결되어 있기 때문에 사용자와 터미널의 연결이 끊기면 종료됨

```text
톰캣 같은 서버 프로세스는 항상 실행되어 있어야 한다. 
클라이언트가 API를 요청하는데 서버 프로세스가 실행 중이 아니라면 사용자 요청을 처리할 수 없기 때문이다.
이러한 이유로 서버 프로그램은 포그라운드 프로세스로 실행하지 않고 백그라운드 프로세스로 실행한다.

백그라운드 프로세스는 터미널과 연결되지 않은 프로세스를 말한다.
터미널과 연결되어 있지 않으므로 키보드나 스크린을 통해 사용자와 상호작용할 수 없다.
리눅스에서 프로세스를 백그라운드로 실행하려면 명령어 뒤에 &를 붙이면 된다.
```

> 2>&1 <br/>
> 리눅스를 사용하다 보면 `2>&1`이라는 표현을 자주 보게 된다. `2>&1`에서 각 항목은 다음을 의미한다. <br/>
> - `2`: 표준 오류 (System.err.println 메서드로 출력하면 표준 오류로 출력됨) <br/>
> - `>`: 리디렉션 연산 <br/>
> - `&1`: 표준 출력 <br/>
> <br/>
> 즉, `2>&1`은 표준 오류를 표준 출력과 동일한 경로로 전달하라는 의미이다.

**alias 등록하기**
- 리눅스에서 alias는 명령어에 대한 별칭
- 2가지 등록 방식
  - 현재 터미널 세션에만 적용하는 방식 <br/>
  ```shell
   $ alias cdweb='cd /var/www/html'
  ```
  - 매번 설정하지 않고 로그인할 때 자동으로 alias를 적용하고자 한다면, shell의 구성 파일에 alias를 등록 <br/>
  홈 디렉토리에 위치한 `.bashrc`파일 하단에 alias 설정을 추가 <br/>
  ```shell
    # .bashrc
    # Source global definitions
    if [ -f /etc/bashrc ]; then
            . /etc/bashrc
    fi 
    # alias
    alias cdweb='cd /var/www/html'
  ```
- 인자 없이 `alias`만 실행하면 현재 정의되어 있는 모든 별칭을 볼 수 있다.

**네트워크 정보 확인**
- `ifconfig`: 네트워크 카드(NIC / Network Interface Card)의 상태를 확인하고, IP 주소나 마스크 같은 네트워크 설정을 관리하는 명령어
  - 주요 정보
    - `IP 주소(inet)`: 172.19.187.60
    - `IPv6 주소(inet6)`: fe80::215:5dff:fec3:f66b
    - `MAC 주소(ether)`: 00:15:5d:c3:f6:6b

- `nc`: 특정 포트로 연결이 잘 되는지 확인할 때 사용하는 명령어 
  - -z 옵션: 데이터 전송 없이 특정 포트가 열려 있는지만 확인
  - -v 옵션: 추가 정보를 출력
  - -u 옵션: UDP 포트가 열려있는지 확인
  - -l 옵션: 리스닝(listening) 모드 = 서버 모드
  - -p 옵션: 클라이언트 요청을 수신할 포트를 지정하는 옵션
  - ```shell
    $ nc -z -v www.daum.net 443
    Ncat: Version 7.92 (https://nmap.org/ncat)
    Ncat: Connected to ::1:6100.
    Ncat: UDP packet sent successfully
    Ncat: 1 bytes sent, 0 bytes received in 2.01 seconds.
    ``` 
- `netstat`: 현재 서버에서 열려 있는 서버 포트를 확인할 수 있다. <br/>
    현재 사용 중인 소켓의 IP와 포트를 확인 할 수 있다.
  - -l: 리스닝 서버 소켓 출력
  - -p: 소켓을 사용하는 PID/프로그램 이름 출력
  - -u: UDP 소켓을 출력
  - -t: TCP 소켓을 출력
  - -n: 포트나 주소를 숫자로 출력
  - `간혹 클라이언트 소켓이 같은 포트 번호를 사용하면서 포트 충돌이 발생할 수 있음, 클라이언트 소켓이 사용할 포트 범위 제한하여 방지`
