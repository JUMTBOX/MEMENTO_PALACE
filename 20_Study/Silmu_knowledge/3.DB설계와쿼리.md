## 3. DB 설계와 쿼리

**인덱스**
- LIKE 검색 시 발생할 수 있는 FULL SCAN을 막는 전문 검색(FULL-TEXT SEARCH) 기능
```markdown
FULLTEXT는 LIKE '%keyword%'를 인덱스로 가속하는 기능이 아니라, 
문자열을 토큰으로 분해해 별도의 역색인(Inverted Index)을 만들고 검색하는 완전히 다른 검색 방식
```

```sql
# 인덱스 만들기
CREATE FULLTEXT INDEX ft_index_title_text ON table(title);

# projection
SELECT 
    * 
FROM table
WHERE MATCH(title) AGAINST('example');
```

**단일 인덱스와 복합 인덱스**

**선택도를 고려한 인덱스 column 선택**
- 선택도(selectivity)가 높은 컬럼을 골라야 함
- 선택도란 인덱스에서 특정 컬럼의 고유한 값 비율이고 선택도가 높으면 고유한 값이 많다는 뜻임
  <br/> (다만 선택도가 낮다고 하여 인덱스로 사용하지 못하는 것은 아님...)

**커버링 인덱스 활용하기**
- 특정 쿼리를 실행하는 데 필요한 칼럼을 모두 포함하는 인덱스
```sql
# index (activityDate, activityType)

# 인덱스를 이용하여 읽을 데이터를 빠르게 선택할 수 있지만, 
# 인덱스에 포함 된 컬럼들을 제외한 나머지 컬럼들의 값을 조회하기 위해 각 데이터에 접근해야 한다.  
SELECT * FROM activityLog WHERE activityDate = '2026-07-20' AND activityType = 'VISIT';  

# 쿼리를 실행하는 데 필요한 activityDate, activityType 
# 각 컬럼 값이 모두 인덱스에 포함되어 있기 때문에
# 실제 데이터를 읽어오는 과정이 생략되므로 쿼리 실행 시간이 빨라진다.  
SELECT activityDate, activityType FROM activityLog WHERE activityDate = '2026-07-20' AND activityType = 'VISIT';  
```
