**🔑인덱스**
- LIKE 검색 시 발생할 수 있는 FULL SCAN을 막는 전문 검색(FULL-TEXT SEARCH) 기능
```markdown
FULLTEXT는 LIKE '%keyword%'를 인덱스로 가속하는 기능이 아니라, 
문자열을 토큰으로 분해해 별도의 역색인(Inverted Index)을 만들고 검색하는 완전히 다른 검색 방식
```

```sql
# 인덱스 만들기
CREATE FULLTEXT INDEX ft_index_title_text ON table(title);

# projection
SELECT 
    * 
FROM table
WHERE MATCH(title) AGAINST('example');
```

**🔑상태 변경 기능은 복제DB에서 조회하지 않기**
- Write는 주DB, Read는 복제DB에서 하는 case
- 주DB와 복제DB는 순간적으로 데이터가 일치하지 않을 수 있다...
- 주DB와 복제DB 간 데이터 복제는 트랜잭션 커밋 시점에 이루어진다. <br/>
  주DB의 트랜잭션 범위 내에서 데이터를 변경하고, 복제 DB에서 변경 대상이 될 수 있는 데이터를 조회하면 데이터 불일치로 인해 문제가 생긴다.

**🔑테이블 변경 주의**
- MySQL은 테이블을 변경할 때 새 테이블을 생성하고 원본 테이블의 데이터를 복사한 뒤, 복사가 완료되면 새 테이블로 대체
- 복사 과정중 UPDATE, INSERT, DELETE 같은 DML 작업을 허용하지 않기 때문에 복사 시간만큼 서비스가 멈춘다


## 더 알아보기

### Online DDL이 무엇인가
- DB테이블 구조(스키마)를 변경하는 동안에도 서비스 중단 없이 INSERT, UPDATE 등의 DML 작업을 계속 처리할 수 있게 해주는 기능

```sql
ALTER TABLE 테이블명 ADD COLUMN 새컬럼명 데이터 타입,
ALGORITHM = INPLACE,
LOCK = NONE;
```
- `ALGORITHM`: 변경 작업을 어떤 방식으로 처리할지 결정 
  - `INPLACE`: 테이블 데이터를 다른 곳으로 복사하지 않고 기존 위치에서 직접 수정
  - `COPY`: 예전 방식, 임시 테이블을 만들어 데이터를 모두 복사한 뒤 바꿈
  - `INSTANT`: MySQL 8.0 이상에서 지원하며, 메타데이터만 살짝 변경하여 최단 시간에 작업 종료

- `LOCK`: DDL이 실행되는 동안 읽기/쓰기를 얼마나 허용할지 결정
  - `NONE`: Read, Write 모두 허용 (무중단 서비스 필수 옵션)
  - `SHARED`: Read만 허용하고 Write는 막음
  - `EXCLUSIVE`: Read, Write 모두 막고 테이블을 완전히 잠금

**작업별 지원 범위 (MySQL 8.0+ 기준)**
- 작업 종류에 따라 사용 가능한 알고리즘이 자동으로 결정되지만, 명시적으로 적어두면 지원하지 않는 방식일 때 에러를 내주므로 안전
  - `컬럼 추가 (끝에 추가)`: ALGORITHM=INSTANT 지원 (가장 빠름)
  - `컬럼 추가 (중간에 추가)`: ALGORITHM=INPLACE, LOCK=NONE 지원
  - `인덱스 추가/삭제`: ALGORITHM=INPLACE, LOCK=NONE 지원
  - `컬럼 데이터 타입 변경`: ALGORITHM=COPY만 지원 (이때는 LOCK=NONE 설정 시 에러 발생하므로 주의 필요)
